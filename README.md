Асинхронный сервис для сокращения ссылок с поддержкой пользовательских коротких кодов и срока действия. Обеспечивает редирект и сбор статистики переходов. Оптимизирован для высоких нагрузок на чтение с пропускной способностью более 2600 RPS.

---

## Технологический стек

- **Язык и фреймворк:** Python 3.14, FastAPI, Pydantic v2, Pydantic Settings
- **База данных и ORM:** PostgreSQL 18, SQLAlchemy 2.0 (asyncio), asyncpg, Alembic
- **Кэш и фоновые задачи:** Redis 7, Celery, Celery Beat
- **Шлюз:** Nginx 1.27 (Reverse Proxy, Rate Limiting)
- **Управление проектом:** uv, Ruff (linter/formatter), Pyright (strict static typing)
- **Тестирование:** Pytest, pytest-asyncio, pytest-cov (code coverage), Testcontainers (Postgres, Redis)
- **CI/CD:** GitHub Actions (Ruff, Pyright, Testcontainers и публикация образа в GHCR)

## Быстрый запуск

### 1. Клонирование репозитория и настройка окружения
```bash
git clone https://github.com/KhakimBalazhonov/url-shortener.git
cd url-shortener
cp .env.example .env
```

### 2. Запуск через Docker Compose
```bash
docker compose up -d
```

После старта доступны следующие сервисы:
- **API и Swagger UI:** [http://localhost/docs](http://localhost/docs)
- **База данных PostgreSQL:** `localhost:5432`
- **Кэш Redis:** `localhost:6379`
- **Фоновые воркеры Celery**

## Архитектурные решения

### 1. Выбор типа редиректа: `302 Found` вместо `301 Moved Permanently`
- **301 Moved Permanently:** браузер кеширует перенаправление в локальной памяти. Все последующие переходы идут напрямую на целевой ресурс в обход бэкенда. Это исключает нагрузку на сервер, но делает невозможным подсчет кликов и проверку срока жизни ссылки (`expires_at`).
- **302 Found (выбранное решение):** браузер каждый раз обращается к бэкенду, что позволяет вести аналитику по каждому переходу и проверять срок действия ссылки.

### 2. Длина короткого кода (Base62)
- Используется алфавит Base62: `a-z`, `A-Z`, `0-9` (всего 62 символа).
- Длина в 6 символов обеспечивает $62^6 \approx 56.8$ млрд уникальных комбинаций (7 символов вмещают 3.5 трлн).
- При исчерпании 6-значного диапазона длина новых кодов увеличивается автоматически, старые ссылки при этом не меняются.

### 3. Генерация кодов без коллизий и защита от перебора (`Sequence` + `Sqids`)
- **`PostgreSQL SEQUENCE`**: выдает уникальный числовой ID для каждой ссылки. `CACHE 1000` резервирует значения пачками по 1000, сокращая обращения к базе данных.
- **`Sqids`**: преобразует полученный ID в короткий буквенно-цифровой код длиной от 6 символов (например, `IU1Bkp`). Это скрывает реальное число записей в базе данных и защищает от перебора ссылок по порядку (`/1`, `/2`).
- **Секретный алфавит как приватный ключ**: вместо стандартного публичного алфавита `Sqids` используется случайная перестановка 62 символов, хранящаяся в `.env`. Без этого алфавита невозможно вычислить исходный номер или предсказать следующий короткий код.
- **Гарантия уникальности:** для автоматически сгенерированных кодов вероятность коллизии математически равна 0%. Для кастомных кодов предусмотрена обработка ошибки уникальности (`409 Conflict`).

### 4. Кэширование и подсчет переходов (Redis)
- **Кэширование ссылок**: если ссылка найдена в оперативной памяти Redis, ответ отдается без обращения к БД.
- **Подсчет кликов**: вместо обновления PostgreSQL при каждом переходе, счетчик увеличивается в Redis (`INCR clicks:{code}`). Celery периодически переносит накопленные значения в БД.
- **Защита от спама несуществующими ссылками**: если код не найден в БД, Redis сохраняет специальную метку `__NOT_FOUND__` на 60 секунд. Повторные запросы к этому коду обрабатываются без обращения к БД.

### 5. Фоновые задачи (Celery + Celery Beat)
- **Очистка просроченных записей:** Celery Beat запускает задачу удаления ссылок с `expires_at < now()`.
- **Оптимизация очистки**: для `expires_at` создан частичный индекс с условием `WHERE expires_at IS NOT NULL`. Бессрочные ссылки не попадают в индекс, что уменьшает его размер и ускоряет поиск ссылок с истекшим сроком действия.

### 6. Инфраструктура и защита
- **Nginx Rate Limiting:** шлюз ограничивает частоту запросов. При превышении возвращается статус 429 Too Many Requests.
